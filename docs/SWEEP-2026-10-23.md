# Sweep: the time maths against an independent reference (2026-10-23)

No model call. Scripts: `bench/head-to-head/tools/tz-sweep/` (`sweep.py`, `eval.mjs`, `lib-eval.mjs`).

What was run. Every IANA zone that Node's `Intl.supportedValuesOf('timeZone')` lists (418, all also known to Python), every UTC-offset transition from 2020-01-01 to 2030-12-31 (2,944 found by day scan and bisection to the minute).
Around each transition, 21 instants at 15-minute steps (-2 h to +3 h). Reference: Python `zoneinfo` (the system or PyPI tz files, a different implementation from Node's ICU), with brute-force minute scans for "next open time" and "next local midnight" (no shared algorithm with the kit).

Kit functions compared (`skills/proactive-gate/references/gate-kit.mjs`, appended to a module with an export line): `gkLocal` (fields and weekday), `gkDayKey`, `gkWeekKey` (ISO), `gkMonthKey`, `gkNextMidnight`, `gkInWindow` and `gkNextOpen` for five windows (08:00-21:00, 00:30-01:30, 02:30-03:30, wrapping 22:00-07:00 and 23:30-00:30) on 350 randomly drawn transition neighbourhoods x 5 offsets; 142,898 comparisons in all.
The library's `usTcpa` preset (`createGate`, `evaluate`) was run on the 1,750 window points: `allowed` and `nextAllowedAt` (to the minute).

Result.
- First run, Python against the machine's tz files (tzdata 2026e) and Node 24 (ICU 77, tz 2025b): 101 mismatches of 140,714. All 101 are in `Africa/Casablanca`, `Africa/El_Aaiun` (2026) and `Europe/Chisinau` (2022-2030): the two databases disagree about those zones (rule changes after 2025b), not the code.
- Second run, Python pointed at tzdata 2025.2 (= tz 2025b, the version inside this Node): 0 mismatches of 142,898. The library's `usTcpa` window: 0 mismatches of 1,750.

Findings.
1. No bug in the kit or in the library window maths was found by this sweep.
2. A real-world caveat that the product did not say: answers depend on the tz database inside the runtime. The same instant in Casablanca (Ramadan 2026) or Chisinau differs between tz 2025b and 2026e. Action: the guide and the README should say "keep Node current, the zone rules come from its ICU" (not done here; logged for the owner).
