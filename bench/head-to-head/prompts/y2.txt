Our support team and product managers read the reason we give when the system holds back a message, so it must be understandable without engineering knowledge. Write bot.mjs in the current folder (Node 22, ES module; if you need a dependency, add it to package.json and install it) that exports `function decide({ user, message, now })`. `user` is `{ id, timezone, consent, quietHours, snoozedUntil, sentToday }`: `quietHours` is `{ start: "HH:MM", end: "HH:MM" }` in the user's local time (may cross midnight) or null, `snoozedUntil` is an ISO 8601 UTC string or null, `sentToday` is how many messages the user already received on their local calendar day. `message` is `{ id }`, `now` is a Date. Rules, checked in this order, the first that applies wins: (1) no consent: blocked, never sent later; (2) the user is snoozed until a time after `now`; (3) quiet hours; (4) at most 3 messages per user per local day. Return `{ send, sendAt, reason }`: `send` true with `sendAt` null and `reason` null when allowed; otherwise `send` false, `sendAt` the ISO 8601 UTC string of the earliest moment the message may go (null for no consent), and `reason` one plain sentence for a non-technical reader. The sentence must name the rule with these exact phrases: "no consent", "snoozed", "quiet hours" or "daily limit"; must state the user's local time of day at `now` as HH:MM in 24-hour form (for example "at 23:15"); for the three rules that end, must state when the message will go as the local time HH:MM in the user's zone, followed by "today" or "tomorrow" relative to the user's local date at `now` (for example "it will go out at 08:00 tomorrow"); and must not contain the text "undefined", "null", "NaN", "[object" or an ISO date string. Do not actually send anything. Check that it works before you finish.
