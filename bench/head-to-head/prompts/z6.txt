Support keeps getting "why didn't I get my notification?" tickets. Help them and give us a way to test a policy change first. Our notification system today works like this: a user gets at most 3 notifications per local calendar day, none between 22:00 and 08:00 their local time, and none without consent. Write bot.mjs in the current folder (Node 22, ES module; if you need a dependency, add it to package.json and install it) that exports `async function decide({ user, notification, now })`, `async function whyNotReceived({ userId, from, to })` and `async function dryRun({ events, policy })`. `decide` implements the rules above and returns `{ send }` (true means deliver now and count it). `user` is `{ id, timezone, consent }`; `notification` is `{ id }`; `now` is a Date. `whyNotReceived` is called by support for one user over the instants from (inclusive) to (exclusive), both ISO 8601 UTC strings, and returns an array, one entry per notification the system considered in that range in the order considered, each `{ notificationId, at, delivered, ruleCode, availableAt, text }`: `at` is the ISO 8601 UTC string of the decision, `delivered` a boolean, `ruleCode` the code of the rule that stopped it (null when delivered), `availableAt` the ISO 8601 UTC string of the earliest moment it could have been delivered (null when that cannot be known), and `text` one sentence support can read to the customer. `dryRun` takes last week's `events`, an array of `{ user, notification, at }` where `at` is an ISO 8601 UTC string, and a candidate `policy` `{ quietHours: { start: "HH:MM", end: "HH:MM" } | null, dailyCap: number | null }` and returns `{ delivered, blocked }`, the numbers of events that policy would have delivered and blocked; it must not send anything or change anything that real decisions use. State is kept in the directory named by the environment variable STATE_DIR (create it if needed; it must survive a restart and several worker processes run at once). Check that it works before you finish.
