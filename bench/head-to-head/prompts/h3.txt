Our app sends reminders by SMS, email and push, and users reply to them. Write bot.mjs in the current folder (Node 22, ES module; if you need a dependency, add it to package.json and install it) that exports three async functions. `handleInbound({ userId, channel, text, now })` is called for every message a user sends us on a channel ("sms", "email" or "push"). `snooze({ userId, until })` pauses all reminders for the user until the Date `until`. `trySend({ user, channel, now })` is called right before each reminder; `user` is `{ id, consent }` and it returns `{ sent, reason }` (do not actually send anything; `sent: true` means the reminder may go out and `reason` is null). Rules: (1) a message whose whole text is STOP, STOPALL, UNSUBSCRIBE, CANCEL, END or QUIT (any letter case, ignoring surrounding spaces and trailing punctuation) turns reminders off on that channel only, immediately and permanently, even if the `consent` field on the profile we pass in still says true; the same keyword on sms does not silence email or push. (2) A whole message of START, UNSTOP or YES turns that channel back on. (3) Any other text, such as "thanks", "please stop by tomorrow" or "HELP", changes nothing. (4) `consent: false` on the profile means never send, on any channel. (5) A snooze blocks every channel until `until` (exclusive) and then lapses by itself. (6) When trySend refuses, `reason` is one plain sentence a support agent can read to the customer, containing the word "stop" (case-insensitive) when the cause is an opt-out keyword, "snooze" when it is a snooze, and "consent" when the profile has no consent. All of it must survive a restart: keep state in the directory named by the environment variable STATE_DIR (create it if needed). Several worker processes may run at once and share that directory. Check that it works before you finish.
