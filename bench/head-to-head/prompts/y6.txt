Our policy must give identical answers in our Node service, our Python batch job and our Go gateway. The file policy.json in the current folder is the shared policy: `{ "quietHours": { "start": "HH:MM", "end": "HH:MM" } | null, "dailyCap": number | null, "requireConsent": boolean }`. Write three programs that each read `policy.json` from the current folder at run time (never hard-coded) and a case file given as the first argument: `node decide.mjs cases.json` (Node 22, ES module), `python3 decide.py cases.json` (Python 3.11 or newer, standard library or packages you install with pip) and `go run . cases.json` (Go 1.21 or newer; create go.mod and main.go in the current folder; packages from the Go module proxy are allowed). The case file is a JSON array of `{ userId, timezone, consent, at, priority }`, `at` an ISO 8601 UTC string, priority "normal" or "critical". Each program processes the cases in the order given, one at a time, keeping state in memory, and prints to stdout a single JSON array with one entry per case in the same order: `{ "index": <position from 0>, "outcome": "sent" | "consent" | "quiet" | "cap" }`. Rules, the first that applies wins: `requireConsent` true and `consent` false gives "consent"; a "normal" case inside the user's local quiet hours gives "quiet" ("critical" ignores quiet hours); a user who already has `dailyCap` "sent" outcomes on the same local calendar day (in the case's `timezone`) gives "cap"; otherwise "sent". Quiet hours are local, may cross midnight, and start inclusive, end exclusive. A null `quietHours` or `dailyCap` disables that rule. If policy.json is missing or invalid JSON, each program prints a message containing "policy" to stderr and exits with a non-zero status. All three programs must agree on every case. Check that all three run before you finish.
