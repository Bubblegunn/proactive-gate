A user wrote to support: "I never get any messages from you." Support needs to see exactly why. Write bot.mjs in the current folder (Node 22, ES module; if you need a dependency, add it to package.json and install it) that exports `async function deliver({ user, message, now })` and `async function whyNothing({ userId, from, to })`. `user` is `{ id, timezone, consent }`, `message` is `{ id }`, `now` is a Date. `deliver` decides and records every call, allowed or blocked, durably, in the directory named by the environment variable STATE_DIR (create it if needed), shared by several worker processes and surviving restarts. Rules, the first that applies wins: no consent (rule "consent"); quiet hours 22:00 to 07:00 in the user's local time (rule "quietHours"); at most 2 delivered messages per user per local calendar day (rule "dailyCap"). `deliver` returns `{ delivered: true, rule: null }` or `{ delivered: false, rule }`. `whyNothing` answers for one user over the instants from (inclusive) to (exclusive), both ISO 8601 UTC strings, from what was recorded: `{ delivered, blocked, byRule, verdict }`. `delivered` is the number of delivered messages in the range; `blocked` lists, ordered by time then by arrival, `{ messageId, at, rule, reason }` for each blocked message (`at` is the ISO UTC string of that call's `now`, `reason` one plain sentence containing the rule's word: "consent", "quiet hours" or "daily limit"); `byRule` maps each rule name to its count of blocked messages; `verdict` is one plain sentence: when nothing was delivered and something was blocked, it contains "nothing was delivered" and names the rule that blocked the most messages by its phrase ("consent", "quiet hours" or "daily limit"); when nothing was recorded at all in the range it contains "no messages"; otherwise it contains "delivered". Several worker processes may call `deliver` at the same time and no record may be lost, duplicated, or let a third delivery through in one local day. Check that it works before you finish.
