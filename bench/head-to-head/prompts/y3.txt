Before we change our notification policy we want to replay last week's messages under the proposed policy and see what would have changed and which rule stopped each message. Write bot.mjs in the current folder (Node 22, ES module; if you need a dependency, add it to package.json and install it) that exports `function replay({ events, policy })` and `function compare({ events, policyA, policyB })`. An event is `{ id, userId, timezone, at, priority, consent }` where `at` is an ISO 8601 UTC string, `timezone` an IANA name, priority "normal" or "critical", and `consent` a boolean. A policy is `{ requireConsent, quietHours, dailyCap, weeklyCap }`: `requireConsent` boolean; `quietHours` is `{ start: "HH:MM", end: "HH:MM" }` in the user's local time (may cross midnight) or null; `dailyCap` and `weeklyCap` are numbers or null, counted per user per local calendar day and per local ISO week (Monday 00:00 to Sunday 24:00). A "critical" event ignores quiet hours but not consent or the caps. `replay` processes the events in time order (ties keep input order; the input array may be in any order and must not be modified), each exactly once, and returns `{ decisions, counts, byRule }`. `decisions` lists in processing order `{ id, outcome, rule, holdUntil }`: outcome "sent" (rule null, holdUntil null) which then counts against both caps of its user; "held" when quiet hours stop it (rule "quietHours", holdUntil the ISO UTC string of the moment quiet hours end); "refused" otherwise (rule "consent", "dailyCap" or "weeklyCap", holdUntil null). Rules are checked in the order consent, quietHours, dailyCap, weeklyCap and the first that applies decides; held and refused events consume nothing and are not retried. `counts` is `{ sent, held, refused }`; `byRule` maps each rule name that stopped at least one event to how many it stopped. `compare` replays under both policies and returns `{ countsA, countsB, byRuleA, byRuleB, changed }` where `changed` lists in processing order `{ id, from, to }` for every event whose outcome or rule differs, with `from` and `to` as `outcome` or `outcome:rule` strings (for example "sent" and "refused:dailyCap"). Pure computation: no network and no files. Check that it works before you finish.
