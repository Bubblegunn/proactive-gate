Our retail app messages customers by SMS, email and push, and we have a rule: no customer gets more than 2 marketing messages a day, whatever the channel. A day means midnight to midnight in the customer's own time zone. The marketing sender runs as several Node 22 worker processes at the same time, and they restart from time to time. Right now a customer can get a fourth message in a day because every worker keeps its own count, and when I look at the logs I cannot tell which message should have been held.

Please write bot.mjs (ES module) exporting `async function reserve({ userId, timeZone, channel, now })`. A worker calls it just before it sends a marketing message. `userId` is a string, `timeZone` an IANA name such as "Asia/Tokyo", `channel` is "sms", "email" or "push", and `now` is a JavaScript Date that I pass in, so do not read the system clock. It returns `{ allowed: boolean, rule: string }`. If `allowed` is true the worker sends the message right away, so the function has to remember it. If `allowed` is false, `rule` is a short identifier of your choosing (for example "daily-cap") for the rule that stopped it; when allowed it is the empty string.

All workers share the directory named by the environment variable STATE_DIR, and the state has to survive a restart of every process. Use that directory for everything you store; you may need to create it yourself. Do not rely on anything being shared between processes except files in that directory, and note that several workers, and several calls inside one worker, can run at the same moment.

Do not actually send anything. Check that it works before you finish.
