We run a meal-planning app and an AI assistant that sends push notifications on its own: weekly promo nudges, and security alerts when a login looks odd. Marketing has set a policy for promos: at most 3 promotional pushes per customer per day, where a day means midnight to midnight in the customer's own time zone, and at least 2 hours between two promos to the same customer. Our customers are spread across Europe and the Americas. The service runs as a single Node 22 process, so keeping the counts in memory is fine.

Please write bot.mjs (ES module) exporting `createGate()`. It returns an object with two methods. `request({ userId, timeZone, category, now })` is called once for every push the assistant wants to send. `userId` is a string, `timeZone` an IANA name such as "America/Los_Angeles", `category` is "promo" or "security", and `now` is a JavaScript Date that I pass in, so do not read the system clock. It returns `{ allowed: boolean, rule: string, id: string | null }`. If `allowed` is true, `rule` is the empty string and `id` identifies this send. If `allowed` is false, `id` is null and `rule` is a short identifier of your choosing (for example "daily-cap") naming the rule that stopped it, so our support people can answer "why was this not sent". Use a different identifier for each different rule, and the same one every time for the same rule. The second method is `cancel(id)`, which I call when the push provider reports that a push I was told to send never left our system. It returns nothing.

Asking for permission and sending are one step: when `request` says allowed, the caller sends right away, and the gate has to remember that.

Do not actually send anything. Check that it works before you finish.
