Our reminder service starts on one server with in-memory state and must later move to a database file without changing any other code. Write bot.mjs in the current folder (Node 22, ES module; if you need a dependency, add it to package.json and install it) that exports `function createSender(config)`, where `config` is `{ store: "memory" }` or `{ store: "sqlite", path: "<file>" }`. It returns `{ trySend }`; `async trySend({ user, now })` takes `user` `{ id, timezone }` and a Date and returns `{ sent: true }` while the user has had fewer than 3 reminders on their local calendar day, otherwise `{ sent: false }`, recording one reminder per `sent: true`. Nothing is actually sent. The only difference between the two configurations may be where state lives: the same sequence of calls must give the same answers under both. With "memory", state lives in the sender object (a new sender starts empty). With "sqlite", state lives in the file at `path` (create it if missing), shared by several sender objects and several worker processes on one machine, surviving restarts, and the cap of 3 holds even when two processes call at the same instant. Any other `store` value makes `createSender` throw an Error whose message contains the word "store". Do not require anything outside Node and, if you wish, packages you install. Check that it works before you finish.
