Our app sends notifications over email, push and SMS. Write bot.mjs in the current folder (Node 22, ES module; if you need a dependency, add it to package.json and install it) that exports `async function notify({ user, notification, now, deliver })`. `user` is `{ id, timezone, preferences }`, where `preferences` maps a channel ("email", "push" or "sms") to true or false (a missing key means allowed). `notification` is `{ id, category, channels }`, where category is "security", "activity" or "marketing" and `channels` lists the channels to try, in order of preference. `now` is a Date. `deliver(channel)` is an async callback that sends on one channel and may throw. Rules: (1) skip any channel the user switched off; (2) nothing goes out during the user's quiet hours, 22:00 to 08:00 in the user's own time zone, except category "security", which ignores quiet hours; (3) at most 3 notifications per user per local calendar day; security notifications are not counted and are never stopped by the cap; (4) when `deliver` throws for a channel, try the next allowed channel in order; a notification that reached no channel does not use up any of the user's 3; (5) the cap must hold even when several worker processes handle the same user at the same instant. Return `{ delivered, channel, reason }`: `delivered` is true when one channel succeeded, `channel` is that channel (else null), and `reason` is null on success, otherwise one plain sentence containing "quiet hours", "daily cap", "opted out" (every listed channel is switched off) or "failed" (every allowed channel threw). Keep state in the directory named by the environment variable STATE_DIR (create it if needed) so it survives a restart. Do not send anything for real. Check that it works before you finish.
