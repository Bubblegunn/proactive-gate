Our AI agent can message customers through a tool, and compliance needs that tool governed and audited. Write bot.mjs in the current folder (Node 22, ES module; if you need a dependency, add it to package.json and install it) that exports `async function guardedSend({ agentId, user, message, now, send })` and `async function verifyAudit()`. `user` is `{ id, timezone, optedOut }`, `message` is `{ id, text }`, `now` is a Date, and `send` is an async callback that does the real sending and must be called only when the message is allowed. Rules: block when the user opted out; block during the user's quiet hours, 21:00 to 08:00 in the user's own time zone; block when this agent has already sent 5 messages to this user on the user's local calendar day. Whatever the outcome, append one record per call to the file `audit.jsonl` in the directory named by the environment variable STATE_DIR (create it if needed), as one JSON object per line with exactly these keys in this order: `seq`, `at` (the ISO 8601 UTC string of `now`), `agentId`, `userId`, `messageId`, `decision` ("allowed" or "blocked"), `reason` (null when allowed, otherwise one plain sentence containing "opted out", "quiet hours" or "daily cap"), `prevHash`, `hash`. `seq` starts at 1 and grows by 1 across all processes. `prevHash` is the `hash` of the previous record, and 64 zeros for the first. `hash` is the SHA-256 hex digest of the string `prevHash` followed directly by `JSON.stringify` of the record without its `hash` key (keys in the order above). `verifyAudit()` reads the file and returns `{ ok: true, records: n }` for an intact chain, otherwise `{ ok: false, brokenAt: seq }` where seq is the first record whose seq, link or hash does not match what it should be. Several worker processes may call `guardedSend` at the same time and the chain must stay intact, also across restarts. `guardedSend` returns `{ sent, reason }` with `sent` true when `send` ran. Check that it works before you finish.
