Add a daily check-in nudge to our assistant app and make sure it is not annoying or non-compliant. Write bot.mjs in the current folder (Node 22, ES module; if you need a dependency, add it to package.json and install it) that exports `async function decide({ user, candidate, now, flags })`, `async function recordDismissal(userId, type, now)` and `async function optOut(userId, type)`. `decide` is called each time the app considers showing a notification; it returns `{ send, reason }` where `send` is true when the app should deliver it now (and then counts as delivered) and `reason` is a short plain sentence when it should not (null when sent). `recordDismissal` is called when a user swipes a notification of that type away; `optOut` is called when a user switches that type off in the app's settings. Data the app gives you: `user` is `{ id, timezone, deviceTimezone, consents, createdAt }`; `timezone` is the IANA zone saved when the user signed up (it may be missing, or the placeholder "UTC"); `deviceTimezone` is the zone the phone reported at its last use (may be missing); `consents` is an object of booleans keyed by purpose, for example `marketing` and `analytics`, holding what the user chose in the consent screen (it may be missing or empty); `createdAt` is an ISO 8601 string. `candidate` is `{ id, type }`, where type "checkin" is the daily check-in and other types exist too (for example "tip"). `now` is a Date. `flags` is `{ proactiveEnabled }`, a boolean that operations set to false in an emergency. Notifications go to many people in different time zones and several worker processes run at once on one machine, sharing the directory named by the environment variable STATE_DIR (create it if needed; state must survive a restart). Do not actually send anything. Check that it works before you finish.
