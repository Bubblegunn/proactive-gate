Our app delivers event notifications from a webhook that retries, and it runs as many worker processes on one machine, sharing files on disk (no Redis or other server). Each user may receive at most 5 notifications per calendar day, where the day is the user's own local day. Write bot.mjs in the current folder (Node 22, ES module; if you need a dependency, add it to package.json and install it) that exports `async function deliver({ user, eventId, now, send })`. `user` is `{ id, timezone }` (IANA time zone name), `eventId` identifies the webhook event, `now` is a Date, and `send` is an async callback that does the real delivery (call it at most once per event, only when delivery is allowed). Rules: (1) never more than 5 sends per user per local day, even with 50 workers calling at the same instant; (2) the same `eventId` for the same user is delivered at most once, even when 10 workers receive the redelivery at once and even when it arrives again days later; (3) a worker can be killed at any point, including in the middle of `send`; after a restart a redelivery of an event whose send was interrupted must NOT call `send` again (we prefer a lost notification to a duplicate), and that interrupted event still counts against the user's 5 for that day; (4) the day resets at the user's local midnight. Return `{ sent: true, reason: null }` after `send` resolved, or `{ sent: false, reason }` without calling `send`, where `reason` is one plain sentence containing "daily cap" when the user is at 5 and "already delivered" for a repeated event. State must be kept in the directory named by the environment variable STATE_DIR (create it if it does not exist) so that it survives a restart. Check that it works before you finish.
