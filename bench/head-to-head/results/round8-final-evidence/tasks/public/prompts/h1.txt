Our alert bot messages US and international users in many time zones. Write bot.mjs in the current folder (Node 22, ES module; if you need a dependency, add it to package.json and install it) that exports `async function decide({ user, message, now })`. `user` is `{ id, timezone, country, quietHours }`; `quietHours` is `{ start: "HH:MM", end: "HH:MM" }` in the user's local time (a window may cross midnight) or null for none. `message` is `{ id, priority, channel }` with priority "normal", "high" or "critical" and channel "sms", "email" or "push". `now` is a Date. Rules: (1) no message goes out during the user's quiet hours, except that a "critical" message may ignore quiet hours. (2) Federal law (47 CFR 64.1200) bars SMS to a recipient in the US (country "US") before 08:00 and from 21:00 onward in the recipient's local time; a critical message does NOT override this. That legal window applies to channel "sms" for country "US" only. (3) If the user has no valid IANA `timezone`, nothing is sent, because local time cannot be known. Return `{ send, holdUntil, reason }`. `send` is true when the message may go right now, with `holdUntil: null`. Otherwise `send` is false and `holdUntil` is the ISO 8601 UTC string of the earliest moment the same message may go out under all the rules that apply (the later of the two when both apply; null when no moment can be computed). `reason` is one plain sentence a support agent can read to a customer: for a quiet-hours hold it must contain the words "quiet hours"; for the legal window it must contain "47 CFR 64.1200"; for a missing or invalid time zone it must contain "time zone". When both rules hold the message, mention both. Do not actually send anything. Check that it works before you finish.
