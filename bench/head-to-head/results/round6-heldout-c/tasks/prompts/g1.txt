I run a small clinic-booking app and we are adding appointment reminders by SMS to our US patients, sent by a scheduler that wakes up every few minutes and looks at the reminders that are due. Before the scheduler hands a reminder to our SMS vendor it must ask your code whether a text to this person may go out right now. Please write bot.mjs, an ES module for Node 22, that exports one synchronous function: checkSms(user, now).

The user argument is a plain object like { id: "u_123", phone: "+13125550142", timezone: "America/Chicago" }. The timezone field is an IANA time zone name that the patient picked in the app, or null or an unrecognised string when they never set one. Patients live all over the US and also in a few other countries, so zones with half-hour offsets can show up too. The now argument is a JavaScript Date for the current instant; the server clock runs in UTC and you must not rely on the machine's own time zone. Your code gets no other input and has no state, and nothing may be read from the network.

It returns an object { allowed: boolean, reason: string, nextAllowedAt: Date | null }. When allowed is true, reason is a short explanation and nextAllowedAt is null. When it is false, reason is a short human-readable sentence that a support person could read to understand why the text was held back, and nextAllowedAt is the earliest Date at which the same text could be re-checked and go out, or null if there is no way to know. Our scheduler will simply retry at nextAllowedAt, so it should not be a moment too early.

These are appointment reminders that the patients did not ask for one by one, so be careful about when we text people; we have had one complaint already. Do not actually send anything. Check that it works before you finish.
