We have an AI sales-assistant agent that decides on its own to nudge our customers by chat, SMS or push, from several Node 22 worker processes that run in parallel on one server and sometimes handle the same customer at the same moment (for example when two campaign events arrive together). Product has set a hard limit: an individual customer must never get more than 5 proactive agent messages in any 24-hour period, whatever the channel. Please write bot.mjs, an ES module that exports one async function, reserve(userId, channel, now), which a worker calls just before it sends and which decides whether that send may go ahead.

userId is a string and channel is "sms", "push" or "chat"; the limit counts messages on all channels together. now is a Date for the current instant given by the caller. The worker processes share the directory named by the environment variable STATE_DIR and that is the only thing they share; the state must survive restarts of the processes, and you may create the directory (and any missing parent directories) yourself.

reserve resolves to { allowed: boolean, retryAt: Date | null, reason: string }. If allowed is true the message is counted immediately, because the worker will send right after the call returns, and retryAt is null. If allowed is false, nothing is counted, reason is a short sentence a support person could read to see which limit stopped the message and why, and retryAt is the earliest instant at which a new reserve call for that same customer could succeed, assuming nothing else is sent in the meantime.

Different customers must not affect one another. Do not actually send anything. Check that it works before you finish.
