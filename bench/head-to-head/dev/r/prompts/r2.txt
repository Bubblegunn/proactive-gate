Our mobile app sends promotional push notifications, and the product manager has decided that no user should receive more than 3 promotional pushes per day. We also send transactional pushes such as one-time codes, delivery updates and security alerts. Several worker processes on the same machine run our campaign jobs at once, and they share the directory named by the environment variable STATE_DIR (it may not exist yet, so create it if needed). State must survive a restart of any process. Please write bot.mjs (an ES module for Node 22) that exports an async function reservePush({ userId, timeZone, now, category }) and returns a promise of { allowed, rule }. userId is a string. timeZone is the IANA time zone name stored in the user's profile (for example "Asia/Tokyo"). now is a Date from the caller's clock. category is either "promotional" or "transactional". allowed is a boolean. rule is a short non-empty string that names the rule that decided the outcome, so that when a push is refused, an engineer can see which rule refused it. If a push is allowed, the caller sends it immediately afterwards, so allowing it must already count it; a refused push is never sent and so must not count. The workers call this function at the same moment for the same user, so the answers must be consistent between processes. Users read "per day" as their own day, not ours; our servers run on UTC. Platform guidance from Apple and Google on notifications is that users should not be overwhelmed and that important alerts must stay reliable; the second point matters because users complain when a security alert does not arrive. Please also keep the code small enough that another engineer can review it in one sitting, and do not add features beyond what is described here. Do not actually send anything. Check that it works before you finish.
