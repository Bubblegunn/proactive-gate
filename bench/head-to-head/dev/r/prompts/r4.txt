We built an AI agent that talks to customers over WhatsApp using the WhatsApp Business Platform, and it can now start conversations by itself, for example to say that a table is free or that a delivery is late. Several worker processes handle webhooks and the agent's own jobs at the same time, and they share the directory named by the environment variable STATE_DIR (it may not exist yet, so create it if needed). State must survive a restart of any process. Please write bot.mjs (an ES module for Node 22) that exports four async functions. recordOptIn(userId, at) is called when the customer ticks the consent box on our website. recordOptOut(userId, at) is called when the customer asks us to stop. recordInbound(userId, at) is called by the webhook each time the customer sends us a WhatsApp message. at is a Date (the time the event happened, not the time the call is made; webhooks sometimes arrive late or out of order). Each of those returns a promise. The fourth function is canSend({ userId, now, kind }), which returns a promise of { allowed, rule }. kind is "freeform" (any text the agent composes itself) or "template" (a message built from a template that Meta has already approved). now is a Date from the caller's clock. allowed is a boolean. rule is a short non-empty string naming the rule that decided the outcome, so that when the agent is stopped, an engineer can see which rule stopped it; use a different name for each reason. userId is a string. Follow the Business Platform's own policy and documentation on business-initiated messages, opt-in and the customer service window, and do not assume anything beyond them. Do not actually send anything. Check that it works before you finish.
