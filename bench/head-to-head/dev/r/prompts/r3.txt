We run an online shop that sells in the United States, the United Kingdom and the European Union, and we are putting an AI agent in charge of email campaigns. Before any email is handed to our mail provider, the agent must call a function that says whether that email may be sent. Please write bot.mjs (an ES module for Node 22) that exports a synchronous function evaluateEmail({ message, recipient }) and returns { allowed, rule }. allowed is a boolean. rule is a short non-empty string naming the rule that decided the outcome, so that when an email is held back, the team can tell which rule held it back; use a different name for each different reason. message has: kind ("marketing" or "transactional"; transactional means things like order receipts, shipping updates and password resets), headers (an object of header name to string value, using the exact standard header names, that the provider will add to the email), and postalAddress (the sender's postal address as a string, or null if the template has none). recipient has: email, country (ISO 3166-1 alpha-2 code), status (one of "active", "unsubscribed", "complained", "hard_bounce", "soft_bounce"), and marketingConsent (true, false, or null when we never asked). Many of our US customers were imported from an old store with no recorded answer (null) and we want to keep mailing those who have not opted out, where the law permits it. The compliance reviewer pointed to the US CAN-SPAM Act, the EU ePrivacy rules and the UK PECR, and to the sender requirements that Gmail and Yahoo published in 2024 for bulk senders. You decide what those require of this function. Do not actually send anything. Check that it works before you finish.
