We run a US retail app that texts customers about orders, restocks and offers, and we are letting an AI agent decide on its own when to text people. I need the gatekeeper that the agent must call before every SMS. Please write bot.mjs (an ES module for Node 22) that exports a synchronous function checkSms({ user, now }) and returns { allowed, rule }. allowed is a boolean. rule is a short, non-empty string that names the single rule that decided the outcome, so that when a text is held back, support can see which rule held it back. Use a different name for each different reason, and also return a rule name when the text is allowed. now is a Date taken from the caller's clock. The user object comes from our CRM and has these fields: id (string), phone (E.164 string), timeZone (an IANA name such as "America/Chicago" that the customer chose in the profile; for some older accounts it is null or an invalid value), smsConsentAt (ISO 8601 UTC string for when the customer ticked the box for marketing texts, or null) and smsOptOutAt (ISO 8601 UTC string for the last time the customer replied STOP, or null). Customers move between consent and opt-out over time, and a customer who replied STOP can tick the box again later. Every message that goes through this function is a marketing or promotional text. Our servers run in a different time zone from our customers, so the machine's local time zone must not matter, and customers in the same state can be in different offsets on the same day of the year. The legal team's worry is the federal rules on telephone solicitations (the FCC's TCPA rules, 47 CFR 64.1200) and what the carriers expect from a texting programme; they said nothing about our own preferences, only that we must not be the reason a customer files a complaint. Do not actually send anything. Check that it works before you finish.
