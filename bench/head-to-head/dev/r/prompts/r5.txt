We run two SMS programmes in the United States from two different numbers: order alerts from 32665 and promotions from 32666. The messages go through a carrier aggregator, and the carriers audit the programmes against the CTIA messaging principles. An AI agent decides when to text people, and I need the module that keeps track of who has asked us to stop. It runs inside one long-lived process, so keeping the state in memory is fine. Please write bot.mjs (an ES module for Node 22) that exports two synchronous functions. handleInbound({ from, to, body, now }) is called for every text a customer sends us: from is the customer's number in E.164 format, to is the number of our programme that received it, body is the text, and now is a Date. It returns the text of the automatic reply that should be sent back to the customer, or null if no automatic reply is needed. canSend({ phone, sender, now }) is called before every outbound text and returns { allowed, rule }: phone is the customer's number, sender is the programme number we would send from, and now is a Date. allowed is a boolean and rule is a short non-empty string naming the rule that decided the outcome, so that when the agent is stopped, an engineer can tell which rule stopped it. The customer's consent itself is recorded by another service, so canSend only needs to reflect what customers have told us by text. Numbers from the old CRM arrive in varied US formats such as "(415) 555-0100" or "415-555-0100", while the aggregator's webhook always sends E.164. Customers type many things into their phones, including full sentences. Please keep to what is described here and do not add endpoints or storage. Do not actually send anything. Check that it works before you finish.
