We built a personal-finance app with a chat assistant. Besides answering questions, the assistant can start a conversation on its own: a "nudge" in the in-app inbox (also mirrored to the user's phone as a notification) when it notices something, such as a bill due soon or unusual spending. We have seen users mute or delete the app because the assistant kept talking to people who were not answering, so I need the gate that decides whether it may start the next nudge.

Write bot.mjs (ES module, Node 22, no npm packages) that exports three synchronous functions. canNudge({ userId: string, timeZone: string }, now) returns { allowed: boolean, reason: string, retryAt: string | null }. timeZone is the IANA name of the user's home zone (always valid) and now is a Date supplied by the caller. canNudge only answers the question; it never changes any state, however often it is called. When the answer is no, retryAt is the earliest instant, as an ISO 8601 UTC string, at which a new call for the same user would say yes if nothing else happens in between; when the answer is yes, retryAt is null. reason is a short lowercase code, different for each different cause, and "ok" when allowed, so that someone reading our logs can see which rule held a nudge back. recordNudge(userId, now) is called by the assistant once a nudge has actually gone out. recordReply(userId, now) is called whenever the user sends the assistant a message of their own. Both return undefined. The app is one long-lived Node process, so state may live in memory.

Our product rules: never two nudges less than 4 hours apart; after 3 nudges in a row that the user has not answered, stay silent for 7 days counted from the third one. Apart from that, think about what a user who trusts the app would expect: they have not given us any right to wake them up, and many of our users are in other time zones than our servers.

Do not actually send anything. Check that it works before you finish.
