I run the notification service for a US pharmacy chain's refill-reminder app. Reminders go out as SMS and our SMS vendor delivers whatever we hand it, so the check has to live in our own code. Each customer record comes from our database as { id: string, phone: string (E.164), timeZone: string, smsConsent: boolean }. timeZone is an IANA name such as "America/Chicago" or "Asia/Kolkata", the zone the customer lives in, recorded at sign-up; for old accounts it can be missing or garbage. Our servers run in UTC, but the code must not depend on the server's zone.

Write bot.mjs (ES module, Node 22, no npm packages) that exports one function, checkSmsWindow(customer, now), where now is a Date supplied by the caller. It is called synchronously once per candidate reminder and must not throw for any input. It returns a plain object { allowed: boolean, reason: string, nextAllowedAt: string | null }. reason is a short lowercase code that tells an on-call engineer why a text was blocked (use a different code for each different cause), or "ok" when allowed. nextAllowedAt is the earliest instant, as an ISO 8601 UTC string, at which the same customer could be texted if nothing else changes, and null when the block is permanent or unknown, or when the text is allowed.

These are promotional-style reminders, so US telephone-consumer law applies (TCPA, 47 CFR 64.1200(c)) together with carrier rules; be careful about what the customer has agreed to and about when they may be contacted. Customers live in many zones, and daylight saving time changes have burned us before.

Do not actually send anything. Check that it works before you finish.
