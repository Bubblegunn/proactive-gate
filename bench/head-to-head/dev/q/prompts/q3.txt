Our SaaS product sends two kinds of email: marketing (product news, upgrade offers, re-engagement mails written by our AI assistant) and transactional (invoices, password resets, security notices). Email jobs are pulled from one queue by several worker processes running on the same machine, and any worker may handle any user. The workers share the directory named by the environment variable STATE_DIR; you may create it if it does not exist. State must survive a restart of any or all workers.

Write bot.mjs (ES module, Node 22, no npm packages) exporting two async functions. tryReserveEmail({ userId: string, kind: "marketing" | "transactional" }, now) resolves to { allowed: boolean, reason: string }, where now is a Date given by the caller. A worker calls it just before it hands an email to the mail provider; when it resolves with allowed true, that email counts as sent from that moment, because other workers may be asking about the same user right now. When it resolves with allowed false, nothing is recorded. reason is a short lowercase code, different for each cause, and "ok" when allowed. recordUnsubscribe(userId, now) resolves to undefined and is called when the user clicks the unsubscribe link in one of our emails (or the one-click List-Unsubscribe request arrives), which can be handled by a different worker from the one that sends their mail.

Product rule: a user gets no more than 2 marketing emails in any 24-hour period. Beyond that, think about what the CAN-SPAM Act (15 U.S.C. 7704(a)(4)) and the Gmail and Yahoo bulk-sender requirements expect from us when someone opts out, and about which emails that does and does not apply to. User ids are arbitrary strings that come from several customer systems.

Do not actually send anything. Check that it works before you finish.
