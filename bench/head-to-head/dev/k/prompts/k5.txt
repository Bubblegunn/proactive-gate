We send one short "weekly digest" email to the people who use our team-notes app: a summary of what happened in their workspace. A scheduler wakes up and asks your code, for each person, whether a digest may go to them now. Please write bot.mjs (an ES module for Node 22) that exports a function shouldSendDigest(user, now). The user argument is an object from our database, and some old accounts lack some fields. It has {id: string, email: string, timeZone?: string | null (IANA name, unknown for some old accounts), unsubscribedAt?: string | null (ISO time of the click on our unsubscribe link, or of a spam complaint), lastBounce?: null | {type: "hard" | "soft", at: string (ISO)}, lastDigestAt?: string | null (ISO time of the last digest we sent this person, null if never)}. A "hard" bounce means the mail provider told us the address does not exist or refuses mail for good. A "soft" bounce is temporary, for example a full mailbox or a server that was down. now is a Date passed in by the caller; never read the clock yourself. The function returns an object {allowed: boolean, reason: string}. The reason is one short sentence that says which rule decided, because our support team reads it. It is pure: no network, no files, no state kept between calls, and it must never throw for any user object shaped like the above. We are a US company and our marketing person says to "stay on the right side of CAN-SPAM and the Gmail and Yahoo bulk-sender rules". Do not actually send anything. Check that it works before you finish.
