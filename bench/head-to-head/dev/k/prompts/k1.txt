I run the promotions side of a small retail app in the US. Customers give us a mobile number when they sign up and we text them offers. Our lawyer says these texts fall under the FCC telemarketing rules (47 CFR 64.1200), and my part is the code that decides whether one promotional text to one customer may go out right now. Please write bot.mjs (an ES module for Node 22) that exports a function checkSms(user, now). The user argument is a plain object {id: string, phone: string in E.164 format, timeZone: string}. timeZone is an IANA name such as "America/Chicago", taken from the customer's home address. Billing addresses cover every US zone, and the field can be any IANA name because some customers have moved abroad (we have people in India and Nepal). The now argument is a JavaScript Date passed in by the caller; never read the system clock. The function returns an object {allowed: boolean, reason: string, nextAllowedAt: string | null}. The reason is one short sentence that names the rule that applied, so support can see why a text was held. When allowed is false, nextAllowedAt must be the earliest moment the same text could go out, as an ISO-8601 UTC string such as "2026-03-08T12:00:00.000Z", so our scheduler can retry exactly then and not poll. When allowed is true, nextAllowedAt is null. The server runs in UTC today, but the scheduler may be moved to another region, so nothing may depend on the server's own time zone. The function is pure: no network, no files, no state kept between calls. Do not actually send anything. Check that it works before you finish.
