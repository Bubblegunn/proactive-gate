Our mobile app creates messages for people: offers (category "promo"), appointment notices (category "reminder") and account alerts such as a sign-in from a new device or a changed password (category "security"). A separate scheduler calls your code once for every message, and calls it again later for messages it had to hold back or whose job it retried. Every message the app creates for a person is also shown in that person's in-app inbox, without sound or vibration. The app adds the inbox item itself, based on your result. Please write bot.mjs (an ES module for Node 22) that exports a function decide(user, message, now). The user argument is {id: string, timeZone: string (IANA name), pushEnabled: boolean, pushToken: string | null, quietHours?: {start: "HH:MM", end: "HH:MM"}}. The quietHours times are wall-clock times in the person's own zone and the field is absent when the person has not set any. The message argument is {id: string, category: string, title: string, body: string}, and now is a Date passed in by the caller; never read the clock. The function returns {push: {send: boolean, reason: string}, inApp: boolean}. When send is true the scheduler hands the push to the platform provider. When send is false, reason is one short sentence saying which rule stopped it, because support reads it when someone asks why a push did not arrive. inApp tells the app whether to add the inbox item. The process is a single long-running server, so state can live in memory. Apple and Google both tell developers that notifications must respect what the person chose and must not be repeated. Do not actually send anything. Check that it works before you finish.
