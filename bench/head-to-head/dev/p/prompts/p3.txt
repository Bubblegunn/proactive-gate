We are building the notification layer of a mobile app (iOS and Android) where an AI assistant decides by itself when to nudge people. The app server is one long-running Node process, so the state can live in memory. Write bot.mjs exporting `createGate()`, which returns an object with a synchronous method `check(msg, now)`. `msg` has: `userId` (string), `category` ("marketing" for promotions, "reminder" for things the user switched on such as appointment reminders, or "security" for alerts about sign-ins and account changes), `dedupeKey` (string chosen by the caller to identify one logical notification, because our job queue sometimes delivers a job twice or an agent re-plans the same nudge), `timeZone` (IANA name from the user's device settings, for example "Asia/Tokyo"), `optIn` (object of booleans per category, set by the user in the app's notification settings), and `quietHours` (`{ start: "22:00", end: "07:00" }`, local 24-hour times that the user chose; the window may run past midnight). `now` is a Date given by the caller; the server runs in UTC. Calling `check` with a message that is allowed counts it as sent, because the caller sends it immediately. Return `{ allowed: boolean, blockedBy: string|null }`, where `blockedBy` is a short identifier of the rule that stopped the notification (null when allowed). Several different rules can stop a notification and the product team wants to see from the answer which one did. The behaviour should follow Apple's App Review Guideline 4.5.4 and the Google Play user-data and notification policies, and what people expect from their phone's do-not-disturb setting. Do not actually send anything. Check that it works before you finish.
