We built a customer-care AI agent that messages customers on its own (check-ins, reminders, offers) over WhatsApp and SMS. Dozens of agent worker processes run in parallel and are restarted often. They share a directory given by the environment variable STATE_DIR, which you may need to create, and state must survive restarts and be consistent across workers. Before any send, a worker calls `requestSend({ userId, now })`, an async function exported from bot.mjs. `userId` is a string and `now` is a Date set by the calling worker. Our terms promise customers that the agent will never contact the same person more than four times in any seven days, and never twice within two hours. This is also in line with the WhatsApp Business messaging policy. If the call returns allowed true, the worker sends right away, so the call itself must record that send. Return `{ allowed: boolean, blockedBy: string|null, retryAt: string|null }`. `blockedBy` is a short identifier of the limit that stopped the message (null when allowed), so that when a customer complains we can see which limit applied. `retryAt` is an ISO 8601 UTC string of the earliest moment at which a request for this person would be allowed again if nothing else is sent in the meantime (null when allowed), so the agent can schedule itself instead of polling. When more than one limit applies, `retryAt` must be a moment at which all of them are satisfied. Many workers can ask about the same person at the same moment. Do not actually send anything. Check that it works before you finish.
